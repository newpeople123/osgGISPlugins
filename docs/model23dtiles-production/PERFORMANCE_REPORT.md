## 2. 阶段耗时分布

以最重的两个资产为例（conversion-report.json `stageTimings`）：

- t03（134k 三角形单体网格）：`proxy_encode_error` 阶段占 ~99%——
  其中三角形级切分后的**每组误差评估**是热点（每组都对代理 BVH 做
  双向 Hausdorff 采样）；
- t04（127 对象 572 三角形）：同样 `proxy_encode_error` 占 ~99%，
  其余阶段（读取/划分/写盘）合计 < 1 s。

热点分析结论：误差评估的采样密度（perTri 起始 7、自适应递减）是主要成本。
当前是正确性优先的实现；手册 9.4 的"评估成本控制"已实现自适应采样，
进一步优化空间在按屏幕重要性筛选拒绝评估（待做，见"未决"）。

## 3. 与旧管线（Phase 0 基线）的对比

| 指标 | 旧管线基线 | 生产管线 | 说明 |
|---|---|---|---|
| t03 tiles | 1（不切分） | 3 | 旧管线无空间划分 |
| t04 tiles | 1 | 127（深度 6） | 同上 |
| 几何重复份数 | 每级 LOD 全量拷贝（3 份） | 父=子树并集简化 1 份 | A-06/A-20 |
| 输出体积 t04 | （基线 outBytes，见 BASELINE §5） | 9.55 MB | 含全部 LOD |
| 误差报告 | 无 | 每瓦片 [lower, upper] | 新增能力 |

注：不做"新管线更快"的声称——新管线多了误差评估与代理简化，
同等质量门槛下（同 SSE、同误差上限）的公平对比需要旧管线先具备
相同的误差/特征保留能力才有意义（手册 13.3 要求）。

## 4. 资源预算执行

- 硬上限默认：200k 三角形/瓦片、20 drawcall/瓦片、8 MiB 内容/瓦片；
- S2 场景实测：`-mb 4096` 下 597 个瓦片超限 → **明确失败**，
  无超限瓦片被输出（手册 0.2：不可行时必须明确失败）；
- 纹理：默认输出 KTX2（S1 场景实测 b3dm 内引用全为 .ktx2）。

## 5. 视觉链路性能

CesiumJS 1.119 + SwiftShader（软件渲染）加载 t02（7 tiles）：
53 帧全部渲染出图，无渲染报错。软件渲染的帧率不代表真机性能，不在此报告。

## 6. 未决 / 风险

1. t03 的 113 s 主要耗在误差评估——大批量生产场景需要按手册 9.4
   进一步做"重要性筛选 + 采样预算上限"；
2. 纹理图集/去重（hash-addressed KTX2 共享）在真实 FBX（123 张纹理）
   上观察到缓存去重生效（`textures/` 每张哈希一个文件），
   但图集合并尚未在真实 FBX 上测量收益；
3. 峰值 RSS t12=235 MiB 主要是大纹理解码；KTX2 压缩器的流式处理可再降。
